# 10.3-10.10报告  
**论文题目：** Waterfall: Scalable Framework for Robust Text Watermarking and Provenance for LLMs  
**代码仓库：** [https://github.com/aoi3142/Waterfall](https://github.com/aoi3142/Waterfall)

---

## 1. 研究动机与问题背景

### 1.1 研究问题
随着大语言模型（LLM）的普及，**文本类知识产权（IP）保护**面临新的威胁：
- LLM 可轻易对文本进行**释义（paraphrasing）**或**重新生成**；
- 甚至可能在未经授权的情况下**用于训练**新模型；
- 现有水印方法在面对 **翻译、改写或微调攻击** 时容易失效；
- 同时，多数方案**缺乏可扩展性（scalability）**，难以支持大量用户。

### 1.2 研究目标
论文旨在提出一种**训练无关（training-free）**、**鲁棒（robust）**且**高可扩展（scalable）**的文本水印框架，
可用于：
- 保护原创文本（文章、代码）；
- 实现 LLM 数据来源溯源（data provenance）；
- 在多语言、多文本类型场景下保持一致性能。

## 2. 问题定义与理论框架

给定：
- 原始文本 \( T_o = [w_1, ..., w_N] \)
- 词表 \( V \)
- 客户唯一水印 ID \( \mu_i \)

定义三个核心操作符：

| 操作符       | 含义                                   |
| ------------ | -------------------------------------- |
| **W(μ, T₀)** | 水印操作，将原文嵌入水印生成 \( T_w \) |
| **A(T_w)**   | 攻击操作，如改写、翻译、二次水印、微调 |
| **V(μ, Tₛ)** | 验证操作，计算文本含水印的置信度分数 q |

### 2.1 四个理想特性（Desiderata）
1. **Fidelity（语义保真）**：保持 \( S(T_o, T_w) ≥ s \)；
2. **Verifiability（可验证性）**：水印可被高精度检测；
3. **Robust Verifiability（鲁棒验证）**：对以下攻击保持有效：  
   - A1：词级替换 / 插入 / 删除  
   - A2：翻译 / 释义  
   - A3：二次水印覆盖  
   - A4：上下文提示攻击（In-context prompting）  
   - A5：未经授权的模型微调  
4. **Scalability（可扩展性）**：支持百万级甚至更大规模水印 ID。

## 3. 方法：WATERFALL 框架设计

### 3.1 LLM 释义器：扩展语义空间
传统 synonym 替换方法仅能局部改写，水印嵌入空间有限。  
Waterfall 通过引入 **LLM 作为释义器（Paraphraser）**：
- 以高语义相似度生成多样文本；
- 显著扩大可嵌入语义支持集 \( T^W_{c,s} \)；
- 提高水印容量与嵌入灵活度。

---

### 3.2 n-gram 水印机制：增强鲁棒性
- 将连续 n 个 token 视作一个信号载体；
- 在每个 n-gram 的生成 logits 中嵌入相同的水印信号；
- 即使部分 n-gram 被修改，其余片段仍可用于验证；
- LLM 自身的语义修正能力可自动保持句意一致。

---

### 3.3 词表置换与正交扰动（核心创新）
Waterfall 在 logits 空间实现语义级水印：

\[
\tilde{L}_j = P^{-1}(k_\pi, F(k_p, \kappa, P(k_\pi, L_j)))
\]

其中：
- **P(kπ)**：基于哈希函数（μ 与上下文 n-gram）生成的词表置换；
- **F(kp, κ)**：添加正交函数族的扰动信号（如傅里叶基、正弦/方波函数）；
- **κ**：控制扰动强度，平衡语义保真与可检测性。

**验证阶段：**
- 统计词频分布 \( \bar{C} \)，计算内积  
  \( q = \langle \bar{C}, F_1(k_p)/\|F_1(k_p)\| \rangle \)；
- 若 \( q ≥ \bar{q} \)，则判定文本含有水印 μ。

---

### 3.4 框架整体流程

**水印嵌入过程：**
1. LLM paraphraser 读取原文 \( T_o \)，生成 paraphrased logits；
2. 每步生成时，对 logits 进行置换与扰动；
3. 输出文本 \( T_w \) 保留语义但隐含可验证信号。

**水印验证过程：**
1. 基于 μ 与 n-gram 上下文重建置换；
2. 统计累积分布；
3. 计算与扰动信号的相关性得分。

## 4. 实验结果与分析

### 4.1 文本水印（C4 数据集）
- 对比方法：**M-BIT** (Yoo et al., 2023) 与 **P-NLW** (Qiang et al., 2023)  
- paraphraser：*Llama-2-13B-hf*  
- 扰动函数：Fourier 基

| 指标           | WATERFALL | M-BIT | P-NLW |
| -------------- | --------- | ----- | ----- |
| STS 相似度     | 0.887     | 0.998 | 0.942 |
| AUROC (验证率) | 0.992     | 0.987 | 0.882 |
| CPU 验证时间   | 0.035s    | 2.61s | 148s  |

**结果分析：**
- κ 可调节语义保真与可验证性的平衡；
- 在翻译、释义、重水印等攻击下仍保持高 AUROC；
- 生成文本流畅度显著优于对比方法。

---

### 4.2 代码水印（MBJSP 数据集）
- paraphraser：*Phind-CodeLlama-34B-v2*  
- 对比方案：**SRCMARKER (2024)**

| 指标                | SRCMARKER | WATERFALL |
| ------------------- | --------- | --------- |
| Pass@10（语义保真） | 0.984     | 0.969     |
| AUROC（验证）       | 0.726     | 0.904     |
| Robust Verif.       | 0.662     | 0.718     |
| 可扩展用户数        | 10⁵       | 10¹³⁰²⁷⁴  |

**结论：**
无需代码规则，Waterfall 仅依赖 LLM paraphraser 即可适配多语言代码。

---

### 4.3 LLM 数据溯源（Data Provenance）
- 使用水印化 ArXiv 摘要对 GPT-2-XL 进行未经授权的微调；
- 每个主题对应唯一 μ；
- 对微调模型多次查询后，仍能识别 μ；
- **结果：**100 次查询即可达到 AUROC = 1.0（100 个客户端）。

→ 首次实验证明：**文本水印可实现模型级数据溯源**。

## 6. 局限性与改进方向

- 对极短文本或强调文体的文本（如诗歌）不适用；  
- 可能引入轻微语义偏移或风格变化；  
- 效果受 paraphraser LLM 能力限制；  
- 未来方向：
  - 设计更强的风格保持型 paraphrasing prompt；
  - 利用 Reflexion 等多轮自修正机制；
  - 扩展到数据真实性与时效性溯源。
